03 / EMBEDDING

查出一个数字向量

词表矩阵 E 的形状为 [词表大小, D]。取出对应的 3 行，就得到 X[3, D]。下面使用 D=4。

X = E[token_ids]
[3] → [3, 4]

一个 Block 的输入 / 输出

输入是每个 token 的特征。输出还是每个 token 的特征，形状通常相同；内容被上下文和非线性变换更新。

X [B, T, D] → Block → Y [B, T, D]

B：批大小；T：本次输入的 token 数；D：隐藏维度。教学算例省略 B=1。

整模型的输入 / 输出

堆叠 L 个 Block 后，通过输出投影得到词表上每个 token 的分数 logits，再选择一个 token。

hidden [B, T, D] × W_vocab [D, V]
→ logits [B, T, V]

V：词表大小。常规生成用最后一个有效位置的 logits 选取下一个 token。

你接下来要抓住的区别：Attention 让不同 token 交换信息；FFN 对每个 token 独立做相同的非线性变换。两者都大量使用乘加，但数据依赖不同。位置也必须编码；现代模型常用 RoPE，在 Q/K 上引入位置信息。

当前 token 看向哪里？

柱长 = 注意力权重。切换 token 或修改输入，观察重新分配。

三个常见疑问

Q/K/V 从哪里来？
同一个输入 X，乘三组不同权重。推理时权重固定，Q/K/V 随输入变化。

QKᵀ 的结果是输出吗？
它只是匹配分数。还需缩放、遮罩、Softmax，再加权求和 V。

加权求和的是 K 还是 V？
是 V。K 用来计算权重，V 提供被聚合的数据。

矩阵采用 X × W 的数学约定。框架中 Linear 权重常存成 [out, in]，执行时使用转置，不能只看文件中的形状。

两条 residual 支路分别保留 X 和 R，在对应的加法器处合并。实现中要对齐数据及 valid。

多头不等于重复同一组结果

不同头使用不同投影。标准 MHA 中 D = H × d，Q/K/V reshape 为 [B,H,T,d]，各头独立计算，然后拼接并乘 WO。分头通常是数据布局变化。

Concat(head₀, …, headH₋₁) W_O
[B,T,H×d] → [B,T,D]

GQA 为什么能减小 KV Cache？

GQA 用 Hkv 个 K/V 头服务 H 个 Q 头，多个 Q 头共享一组 K/V。它改变 K/V 投影与缓存容量，不等于把所有 Attention 计算也同比例减少。

Q: [B,H,T,d]
K/V: [B,H_kv,T,d], H_kv ≤ H
04 / PREFILL, DECODE & KV CACHE

生成文字时，芯片在重复什么？

先处理整段提示词，再逐次处理新 token。KV Cache 把历史 K/V 保存下来，供下一次 Attention 使用。

保存的是每一层自己的 K 和 V

每层有不同权重和输入特征，所以每层都需要独立的缓存。新 token 在该层算出 K/V 后追加到缓存；Q 用来查询，不是常规 KV Cache 的缓存内容。

K_all = Concat(K_past, K_new)
V_all = Concat(V_past, V_new)

Decode 没有“只看自己”

常规单 token Decode 的 Q 只有一行，却要和该层全部可见历史 K 匹配，再读取历史 V。上下文越长，KV 读取与 Attention 工作量越大。

Q [1,d] × K_allᵀ [d,S]
→ scores [1,S] → 输出 [1,d]
生成有一个一步偏移：Prefill 的最后位置 logits 先选出第一个新 token；接着把这个新 token 输入 Decode，才能预测再下一个 token。这里的缓存计数表示已经送入模型处理的 token，不是已经显示的全部输出文字。动画演示缓存流程，没有运行真实语言模型。

模型参数

FFN 使用三次投影的 SwiGLU；S 包含本次处理的新 token。

一层中的矩阵计算MAC 数量
1 MAC = 一次乘法并累加。按常见口径 1 MAC ≈ 2 FLOPs；这里显示的是工作量 GMAC，不是吞吐率 GMAC/s。未计词表输出投影、Norm、RoPE、Softmax、逐元素运算和 padding 开销。

N = B × (Decode ? 1 : S)
Q/K/V/O: N × (2D² + 2D×D_kv)
SwiGLU 投影: 3NDF
Attention QKᵀ + AV:
Decode: 2BSD
Prefill: 2BS²D（完整矩阵口径）
KV 字节: 2 × B × S × L × H_kv × d × bits/8

本页公式为从矩阵尺寸推导的估算。Prefill 使用完整 S×S 矩阵口径；因果 Attention 若仅计算下三角，理论有效乘加约为 BS(S+1)D。实际 kernel 是否省掉上三角取决于实现。KV 容量是有效载荷，不含量化 scale/zero-point、对齐、分页、分配冗余。4 bit 假设紧密打包。

芯片该提供哪些运算和数据通路？

模型运算硬件工作需要注意的数据依赖
Q/K/V、W_O、FFN 投影乘法器、累加器、矩阵分块与权重复用Prefill 多行共享权重；小 batch Decode 共享机会少
QKᵀ 与 AV同一 MAC 阵列可调度复用两边都是动态数据；K/V 随上下文增长
RMSNorm平方、求和、倒平方根、逐元素缩放一行归约完成后才能确定该行缩放系数
Softmax最大值、减法、exp、求和、除法跨可见 token 归约；可采用在线算法分块合并
SiLU / SwiGLU / Residual非线性函数、逐元素乘法和加法保留支路特征，对齐延迟、位宽和量化尺度
KV Cache地址生成、分页/连续存储、读写及 DMA每层缓存分别管理；新 K/V 追加，历史数据复用

为什么 MAC 多，也可能跑不快？

耗时取决于计算量、数据搬运和调度。理想的重叠执行下，下界近似为 max(MAC / 有效 MAC 吞吐率, 字节 / 有效带宽)；不能直接用峰值推算实测延迟。

Prefill 较易形成大矩阵、复用权重；小 batch Decode 常受权重与 KV 读取带宽制约。大 batch、缓存命中、上下文长度都会改变瓶颈。

低位宽，不代表所有步骤都低位宽

W4A4 描述某些算子的权重与激活位宽。乘积、累加器、Norm、Softmax、KV Cache 可采用不同位宽，必须逐项确定。

对称整数量化、scale 在归约组内固定时，y ≈ s_x s_w Σ(q_x q_w)。不同分组 scale 要分别缩放后合并；非零 zero-point 还要修正，不能把每种格式都当成一个统一的 4-bit MAC。

分数矩阵不一定要完整写回外存。FlashAttention 通过分块和在线 Softmax 计算精确 Attention，降低中间结果的外存访问；数学上的 S×S 分数矩阵，不等于必须分配同样大小的外存缓冲。为芯片设计数据流时，应区分“逻辑张量”与“物理存储”。
